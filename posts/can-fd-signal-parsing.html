CAN FD 信号位解析

2026-08-01 · 6 MIN READ · 汽车电子 · CAN FD

CAN FD 简介

CAN FD（CAN with Flexible Data-Rate）是经典 CAN 协议的增强版本。相比传统 CAN， 它主要提升了数据传输能力：单帧负载从 8 字节扩展到 64 字节，并且允许仲裁阶段与数据阶段运行在不同速率。

对座舱仪表来说，这意味着单个报文可以承载更多的信号——但也意味着 DLC 与字节长度不再是线性关系， 报文解析这一步必须显式查表，不能再简单地 len = dlc。

1. 与经典 CAN 的区别

  • 传统 CAN：数据长度最大 8 字节，全程速率固定
  • CAN FD：最大支持 64 字节 Payload
  • CAN FD：仲裁阶段（Arbitration Phase）与数据阶段（Data Phase）可使用不同波特率
  • CAN FD：帧结构新增 FDF / BRS / ESI 位，CRC 多项式也不同

速率切换点由 BRS 位控制。联调时常见的现象是：低速率下一切正常，一开 BRS 就大量错误帧—— 多数是采样点（Sample Point）与 SJW 配置不匹配，而不是信号定义写错了。

2. 报文结构与 DLC 映射

CAN FD 报文由 ID、DLC、Data、CRC 组成。DLC 只有 4 bit，却要表达 0～64 字节，于是采用分段映射：

DLC0–89101112131415
字节数0–812162024324864
canfd_parse.c
/* DLC -> 有效字节数（CAN FD 非线性映射） */
static const uint8_t dlc_to_len[16] = {
    0,1,2,3,4,5,6,7,8,12,16,20,24,32,48,64
};

int canfd_parse(const canfd_frame_t *f, signal_t *out)
{
    if (f->dlc > 15) return -1;      /* 非法 DLC */
    const uint8_t len = dlc_to_len[f->dlc];
    out->raw = motorola_extract(f->data, out->start, out->len);
    return (int)len;
}

注意填充规则：DLC 为 9 时表示 12 字节，但多出来的 3 字节通常填充固定值（常见 0xCC 或 0xAA）。 如果解析时把填充字节当成有效信号，会出现「偶发跳变」的经典问题。

经验：先看 DBC 里的 Signal 定义是否符合 start_byte + length <= dlc_to_len[dlc]， 再去怀疑硬件。九成的「信号乱跳」最后都落在字节数判断上。

3. Motorola 信号排列

汽车电子开发中，主机厂 DBC 常使用 Motorola 格式（Big Endian）定义信号。它的特点是从 MSB 开始、 按字节递减方向排列，位序与 Intel（Little Endian）格式完全相反。

  1. 定位起始位：DBC 中的 start bit 指信号的 最高有效位
  2. 按位递减跨字节：同一字节内向右、跨字节后跳到下一字节的 MSB
  3. 若信号带符号位，需按补码还原；精度与偏移最后再套用 phys = raw * factor + offset

总结

  • DLC 必须查表，不能当长度用
  • 填充字节要按 DBC 约定剔除
  • Motorola 的 start bit 是 MSB，不是 LSB
  • 物理值换算顺序：位提取 → 符号还原 → factor / offset
